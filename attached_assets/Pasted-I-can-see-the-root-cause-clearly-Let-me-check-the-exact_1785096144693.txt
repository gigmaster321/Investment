Root Cause
A session-persistence race condition in admin-auth.ts.

express-session auto-saves the session by wiring into the response's finish event — meaning the PostgreSQL write starts only after the response has been flushed to the network. The browser receives the Set-Cookie header (with the new session ID) and immediately fires the next request (e.g. /api/admin/users). That next request arrives at Express before the DB write completes, so connect-pg-simple finds no row for that session ID and returns an empty session. requireAdmin sees neither isAdmin nor userId and returns 401.

curl never hit this because there's human latency between the two commands, giving the DB write time to finish.

There was a second independent bug: adminApiRequest in Users.tsx spread ...init without defaulting credentials: 'include', so every secondary admin request (profile notes, plan changes, status changes) omitted the session cookie entirely and always got 401.

What Was Fixed
artifacts/api-server/src/routes/admin-auth.ts
Added an explicit req.session.save() call before res.json(). The response is now only sent after the session row is confirmed written to PostgreSQL, eliminating the race.

artifacts/quantum-investments/src/pages/admin/Users.tsx
Added credentials: 'include' as a fixed default in adminApiRequest, before the ...init spread, so all secondary admin API calls correctly send the session cookie.
